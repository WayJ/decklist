# decklist v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A zero-dependency CLI (`decklist`) that installs a project's declared
agent skills via the `skills` CLI engine, with an npm-like manifest
(`decklist.json`) and lockfile (`decklist.lock`).

**Architecture:** Declarative shell over an engine. decklist owns manifest
parsing, install-all orchestration with skip logic, and lockfile recording;
every install action is delegated to the engine adapter (`npx skills`).
All modules are cwd-aware and engine-injected for testability.

**Tech Stack:** Node ≥ 20, ESM, `node:test`, zero runtime dependencies.

**Spec:** `docs/specs/2026-10-04-decklist-design.md`

## Global Constraints

- Zero runtime dependencies; dev dependencies: none (`node:test` only).
  `package.json` scripts: `"test": "node --test tests/"`.
- `"type": "module"`; ESM imports only; Node `>=20` in `engines`.
- Names verbatim: package/bin `decklist`; manifest `decklist.json`; lock
  `decklist.lock`; lock version field `decklistVersion: 1`; engine `name:
  "skills"`, `invocation: "npx skills"`.
- Engine argv base (exact): `["-y", "skills", "add", <sourceArg>, "-y", "-s",
  <selector>, ...passthrough]` where `<selector>` is the manifest `skill`
  value or `"*"`. `<sourceArg>`: no pin → source verbatim; pin +
  `/^[\w.-]+\/[\w.-]+$/` → `https://github.com/<source>/tree/<pin>`; pin +
  anything else → `EngineError` before spawning.
- All JSON files written with 2-space indent and a trailing newline.
- Spawn: `stdio: "inherit"`, `shell: process.platform === "win32"`, command
  `npx` (resolved from PATH).
- Exit codes: 0 success/report; 1 fatal or any entry failure. `list`
  drift/missing/undeclared rows stay 0.
- Commands accept an injected `engine` (defaults to `createSkillsEngine()`
  internally); `out` injectable writer (defaults `process.stdout`).
- Commits: conventional (`feat:`, `test:`, `docs:`, `chore:`).

## Review Focus

1. **Non-TTY hang:** a CI run with no agent flag must never block on the
   engine's skill-choice prompt — expected: `-y` and `-s` always in argv.
   Pinned: Task 4 "always passes -y and -s".
2. **Local key ≠ engine skill name:** the engine's `skills-lock.json` keys by
   engine skill name, so a manifest key that differs makes skip/list never
   match — expected: README convention (name keys after skills, or declare
   `skill` selector) + reinstall-when-unknown behavior. Pinned: Task 4 `-s`
   mapping, Task 5 "reinstalls when lock entry unknown".
3. **`decklist add` atomicity:** engine failure must leave manifest and
   lockfile exactly as before (absent stays absent). Pinned: Task 6.
4. **Undeclared installed skills:** shown as info rows, exit stays 0 —
   a report, not a gate. Pinned: Task 7.
5. **Corrupt JSON** (manifest or lock): one-line `file + reason` error, never
   a raw SyntaxError stack. Pinned: Tasks 2 and 3.

### Task 2: Manifest — read/validate/write `decklist.json`

**Files:**
- Create: `src/manifest.js`

**Interfaces:**
- Consumes: nothing.
- Produces (from `src/manifest.js`):

  - `parseManifest(text: string, file = "decklist.json") -> { skills: Record<string, { source: string, skill?: string, pin?: string }> }` — normalizes string entries to `{ source }`

non-string `pin`; unknown keys inside an entry (only `source`, `skill`,
`pin`). Top level allows only `skills` and `$schema`.

  - `upsertEntry(lock, name, { source, resolved? }) -> lock` (sets or replaces the entry; `resolved` omitted stays omitted)

  });

test("read absent → null; corrupt JSON → LockfileError with file+reason, not SyntaxError", () => {
  assert.equal(readLockfile(dir), null);

### Task 5: `decklist install` — orchestration, skip rules, lock write

**Files:**
- Create: `src/commands/install.js`
- Test: `tests/install.test.js`

**Interfaces:**
- Consumes: `readManifest`, `ManifestError` (Task 2); `readLockfile`,
  `emptyLock`, `upsertEntry`, `writeLockfile`, `dropStale` (Task 3); engine
  shape `{ name, invocation, install, installed }` (Task 4).
- Produces: `runInstall({ cwd, engine, passthrough = [], out }) -> Promise<number>`

Skip rules (exact):
- manifest `pin` present → skip iff `lock.entries[name]?.resolved === pin`
- no pin → skip iff `installed.has(name)` and `lock.entries[name]?.resolved` is defined and `=== installed.get(name).hash`
- otherwise install; on success `resolved = pin ?? engineResolved`, `upsertEntry`

Output lines to `out`: `ok <name>` (skip), `installed <name>`, `failed
<name>: <reason>`; final summary `n installed, m skipped, k failed`. Lock is
written after all entries (with `dropStale` applied). No manifest → message
suggesting `decklist add <source>`, exit 1. Any failure → exit 1.

## Post-review amendments (2026-10-04, from the final whole-branch review)

Corrections to this plan that the review showed were defects, faithfully
implemented before being caught:

- **Task 5 skip rule (review C2):** "pin present → skip iff lock resolved ===
  pin" is wrong as written — it skips without consulting installed state, so
  a fresh clone with a committed lock installs nothing. Amended rule: pin
  skip requires `lock.resolved === pin` **and** the probed skill present in
  engine state. Task 5's original test pinned the wrong behavior and was
  rewritten.
- **Task 1 dispatch (review I1):** the `add` dispatch shape omitted
  `passthrough`; `decklist add <src> -- -a claude-code` silently lost the
  engine flags. Dispatch now goes through `buildCall`, which forwards it.
- **Task 5 output lines (review I2):** the line list omitted the hash-drift
  warning the spec (§5, §8) mandates. `install` now emits
  `drifted <name>: locked <old>, now <new>` on unpinned drift.
- **Task 9 ruling (review I3):** `npm test` is bare `node --test` (the dir
  form fails on modern Node); the README now matches, and carries a
  multi-skill `skill`-selector sentence (reviewer rec 3).
- **Identity probing (review C3):** skip/list identity probes use
  `dep.skill ?? name`, making the README's key≠name escape hatch real.
